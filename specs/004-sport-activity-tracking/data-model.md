# Data Model: Sport Activity Tracking API

## `sport_activities`

| Field | Type | Rules |
|---|---|---|
| `id` | UUID | Primary key, generated by service |
| `user_id` | UUID | Required, `auth.users(id)` cascade delete |
| `date` | DATE | Athlete-local civil date |
| `sport_id` | TEXT | Lowercase slug, 1–64 |
| `sport_name` | TEXT | Trimmed display snapshot, 1–80 |
| `duration_minutes` | INTEGER | 1–1,440 |
| `notes` | TEXT nullable | 1–2,000 when present |
| `created_at` | TIMESTAMPTZ | Server generated |
| `updated_at` | TIMESTAMPTZ | Server generated; unchanged in v1 |

Index `(user_id, date DESC, created_at DESC, id DESC)` supports listing. RLS is enabled and direct
application-role grants are revoked because only the Go API reads this table.

## Existing entities used atomically

On create, upsert `day_participation (user_id, local_date)` with `participated=true`, profile timezone,
and finalization time while preserving any `scheduled_opportunity=true`. Store the response in
`idempotency_records` under scope `sport-activities/create`. Same key/hash replays; mismatch conflicts.

## API model

```json
{
  "id": "uuid",
  "date": "2026-08-02",
  "sport_id": "basketball",
  "sport_name": "Basketball",
  "duration_minutes": 60,
  "notes": "Pickup game",
  "created_at": "2026-08-02T18:30:00Z",
  "updated_at": "2026-08-02T18:30:00Z"
}
```

The API never returns `user_id`, operation keys, or request hashes.
